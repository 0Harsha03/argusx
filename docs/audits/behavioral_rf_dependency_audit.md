# ArgusX v11 — Behavioral RF Dependency Audit

## Objective
This repository verification audit determines whether the Behavioral Random Forest (RF) is architecturally and mathematically independent from the semantic models (SBERT and DistilBERT). This establishes whether the shared RF can safely remain unchanged in ArgusX v11 while bifurcating the semantic layer.

---

## 1. Questions & Code Evidence

### Q1. What is the exact input received by BehavioralAnalyzer?
The `BehavioralAnalyzer` receives **normalized prompt text** (Option B) alongside metadata from the Pattern Engine.

**Code Evidence (`app/detection/behavioral_analyzer.py`):**
```python
    def analyze(
        self,
        text: str,
        pattern_score: float = 0.0,
        pattern_categories: List[str] = None,
    ) -> BehavioralAnalysisResult:
```
**Code Evidence (`app/routing/prompt_injection_route.py`):**
```python
        semantic_result = self._semantic_analyzer.analyze(text)
        behavioral_result = self._behavioral_analyzer.analyze(
            text=text,
            pattern_score=pattern_score,
            pattern_categories=pattern_categories,
        )
```
The arguments passed to `_behavioral_analyzer.analyze()` strictly consist of the normalized string (`text`) and variables derived exclusively from the Pattern Engine (`pattern_score`, `pattern_categories`). It does not receive SBERT embeddings, DistilBERT embeddings, or semantic scores.

### Q2. Exactly where is TF-IDF applied?
TF-IDF is applied internally within the `BehavioralAnalyzer.analyze()` method.

**Complete Execution Trace:**
1.  **`app/services/detection_pipeline.py`**: `raw_prompt` is passed to `normalize_text(raw_prompt)`.
2.  **Pipeline/Router**: The resulting `clean_prompt` string is passed identically to all detection engines.
3.  **`app/detection/behavioral_analyzer.py`**: The method calls `vec = self._vectorizer.transform([text])` where `self._vectorizer` is the `TfidfVectorizer` loaded from `vectorizer.pkl`.
4.  **`app/detection/behavioral_analyzer.py`**: The resulting sparse vector is passed to `self._model.predict_proba(vec)[0]`.

### Q3. Does BehavioralAnalyzer ever call SBERTSemanticAnalyzer?
**No.** `app/detection/behavioral_analyzer.py` contains zero imports for SBERT, `sentence_transformers`, or any semantic analyzer. It never accesses cosine similarity scores.

### Q4. Does BehavioralAnalyzer ever call DistilBERT?
**No.** The file contains zero imports for `transformers` or PyTorch. It never consumes token embeddings or softmax probabilities.

### Q5. Does BehavioralAnalyzer receive any output generated by the semantic layer?
**No.** It receives `text`, `pattern_score`, and `pattern_categories`. The `semantic_score` and semantic embeddings are explicitly generated by a sibling layer and are merged far downstream by the `ThreatScorer`. The Behavioral layer is entirely blind to semantic evaluations.

### Q6. Can the Behavioral RF continue operating identically if SBERT is replaced by DistilBERT?
**Yes.** Because the Behavioral RF operates in complete mathematical isolation from the semantic layer, replacing SBERT with DistilBERT inside the Prompt Injection branch will have exactly zero effect on how the RF vectorizes the string, extracts heuristics, and calculates probability. Absolutely no code inside `BehavioralAnalyzer` requires modification.

---

## 4. Final Verdict

### Option A: Behavioral RF is completely independent.

**Architectural Recommendation:**
The Behavioral RF only consumes normalized text transformed by the shared TF-IDF vectorizer. It computes probabilities and heuristic flags completely independently of any semantic modeling. 

**It can remain untouched in ArgusX v11.** The architectural bifurcation between DistilBERT (Prompt Injection) and SBERT (Cyber Threats) can safely occur directly parallel to the Behavioral RF. Sharing the Behavioral RF across both routes is mathematically sound and guarantees the preservation of validated benchmark behavior.
